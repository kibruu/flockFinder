# Domain Docs

How the engineering skills should consume this repo's domain documentation when exploring the codebase.

## Before exploring, read these

- **`CONTEXT.md`** at the repo root: domain glossary and canonical entity definitions.
- **`docs/adr/`**: read ADRs that touch the area you are about to work in.
- **`docs/GOALS_AND_SCOPE.md`**: product goals, value proposition, and MVP boundaries.
- **`docs/USER_STORIES.md`**: core personas and acceptance criteria.
- **`docs/UI_SPECIFICATION.md`**: "Forest & Field" design system tokens and screen architectures.

## Use the glossary's vocabulary

When naming domain concepts (in issue titles, refactor proposals, database fields, or test names), use the terms defined in `CONTEXT.md`. Do not drift to synonyms the glossary avoids.
